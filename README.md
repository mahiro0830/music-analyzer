# 音楽分析

音声ファイル（mp3・wav・aif・m4a など）を読み込むと、曲全体のコードを解析して、再生に合わせて「いま鳴っているコード」と「次のコード」を表示する Web アプリです（試作版・個人利用）。

ファイルはブラウザの中だけで解析し、どこにも送信しません。

## できること

- 音声ファイルの読み込み（ドラッグ＆ドロップ、またはファイル選択）と、デモ曲での試用。AIFF（.aif・.aiff・.aifc）は Chrome や Firefox が自分では読めないため、アプリで読み込んで WAV に変換して再生します（非圧縮の 8〜32 bit と 32/64 bit 浮動小数点に対応。圧縮された AIFF-C は非対応）
- コードの推定は 2 段階で、画面で切り替えられます（最後に選んだほうを覚えます）
  - **基本**：メジャー・マイナー・7th・Maj7・min7・min7♭5・sus4 と、無音（N.C.）
  - **応用**：基本と同じ区切りのまま、テンション（9・11・13・♭9・♯11 など）、6・dim・aug・7sus4 などの型、分数コード（C/E）まで
- 再生に合わせて、いまのコード・次のコード・コードの残り時間を表示
- コード進行の一覧（押すとそこから再生）、再生速度の切り替え（0.5×・0.75×）
- MIDI での書き出し：いま表示している「基本／応用」のコードを、和音（ピアノ）とベースの 2 トラックの MIDI ファイルにします。コード名はマーカー、推定したキーは調号として入ります。テンポは分からないので 120 BPM 固定とし、拍ではなく秒に合わせて音符を置いているため、元の音声と頭を揃えればそのまま重なります。Chord Roll に読み込むと、同じコード名で表示されます
- キーの推定と、キーに合わせた ♭／♯ の表記（コード表記は Chord Roll と同じ `CMaj7`・`Cmin9`・`G7(♭9)`）

## しくみ

1. 音声を 20ms ごとに、ピアノ 88 鍵それぞれの音の強さに変える（`src/listen.ts`、Chord Roll から流用）
2. 12 音の強さ（クロマ）と、低音域だけの強さ（ベース）にまとめる
3. 各コードの型（構成音と、その倍音）と照合し、ベースが根音に合うコードを優先する
4. コードが切り替わるたびにコストを払う形で、曲全体でいちばん自然なコードの並びを選ぶ（Viterbi）。0.4 秒未満の短いコードは前のコードにまとめる

再生前に曲全体を解析するので、各瞬間の前後の音も判定に使えます（3 分の曲で数秒）。解析は 22.05kHz のモノラルに変換してから行います。

応用は、基本で決まった各コードの区間ごとに次のことをします（`src/advanced.ts`）。

1. 区間の 88 鍵の強さを平均し、低い鍵から順に、その倍音（1 オクターブ上、1 オクターブと 5 度上など）の分を上の鍵から差し引く。こうしないと、強く鳴った C が G や E として数えられてしまう
2. 中音域より上で目立つ音と、基本のコードの構成音を合わせて、コードの音とする。低音域でいちばん強い鍵をベースとする
3. その音の集まりに、Chord Roll と同じコード名の付け方（`src/theory.ts`、Chord Roll から移植）で名前を付ける
4. 転回形（C/E）は基本では「Emin」のように読まれやすいので、基本のコードの音が実際には鳴っておらず、鳴っている音でベースの上に別のコードが組めるときは、そちらを採る

## 精度（デモ曲）

`npm run eval` で、デモ曲（`public/demo/demo.mp3`）を元の MIDI から出したコード（`public/demo/demo.truth.json`）と 20ms ごとに比べます。

| 条件 | 根音 | メジャー/マイナー | 7th まで |
| --- | --- | --- | --- |
| そのまま | 92.3% | 86.2% | 70.6% |
| ピンクノイズ（音楽より 10dB 小さい） | 92.3% | 81.6% | 68.7% |
| ピンクノイズ（5dB 小さい） | 91.9% | 77.7% | 69.6% |
| ドラム（音楽と同じ音量） | 91.5% | 83.3% | 72.5% |

応用の精度は、コード全体（根音・型・テンション・ベースがすべて一致）と、テンションの適合率／再現率で測ります。デモ曲には分数コードがないため、分数コードは合成した曲（`tests/pop.truth.json`、`npm run eval -- tests/pop.truth.json`）で測っています。

| 条件 | コード全体（基本のまま） | コード全体（応用） | テンション 適合率／再現率 | 分数コード |
| --- | --- | --- | --- | --- |
| デモ曲 | 1.8% | 52.8% | 78.9%／83.3% | － |
| デモ曲＋ピンクノイズ（10dB 小さい） | 1.2% | 44.1% | 74.0%／76.4% | － |
| デモ曲＋ドラム（同じ音量） | 1.7% | 52.6% | 82.1%／79.4% | － |
| 合成曲（分数コード入り） | 24.5% | 78.2% | 88.4%／100% | 47.5% |

デモ曲はほとんどのコードにテンションが付いているので、基本のままではコード全体はほぼ一致しません。合成曲の分数コードで外れているのは Amin7/G が C6/G、F/G が G9sus4 になる所で、どちらも同じ音の別の呼び方です。

デモ曲はピアノだけの曲です。ボーカル・ベース・ギターなどが入った曲では下がるはずなので、手持ちの曲での確認が次の課題です。正解のコードがある曲なら `node scripts/eval.ts 曲.mp3 正解.json` で同じように測れます（正解の形式は `public/demo/demo.truth.json` を参照）。

## 開発

TypeScript と Vite で書いています。Node.js 22.18 以上が必要です（テストと測定スクリプトは、Node が TypeScript をそのまま実行します）。

```sh
npm install
npm run dev     # http://localhost:5173
npm run check   # 型チェック
npm test        # 合成した和音でのコード判定テスト（基本・応用）
npm run eval    # デモ曲での正解率（ffmpeg が必要）。noise=pink:10 などでノイズを混ぜられます
npm run build   # 型チェックして dist/ に書き出し（npm run preview で確認）
```

公開するときは、ビルドコマンドを `npm run build`、公開するフォルダを `dist` にします（Cloudflare など）。

## 構成

| パス | 内容 |
| --- | --- |
| `index.html`、`src/style.css` | 画面 |
| `src/main.ts` | 読み込み、再生、表示 |
| `src/worker.ts` | 解析を別スレッドで動かす（やりとりの型もここ） |
| `src/listen.ts` | 音声 → 88 鍵の強さ（DOM に依存しない） |
| `src/chords.ts` | 基本：88 鍵の強さ → コードとキー、コード名（DOM に依存しない） |
| `src/advanced.ts` | 応用：基本の各コードにテンションと分数のベースを足す（DOM に依存しない） |
| `src/theory.ts` | 音の集まり → コード名（Chord Roll から移植）、コード → 構成音 |
| `src/midi.ts` | コード → MIDI ファイル（DOM に依存しない） |
| `src/audio.ts` | AIFF の読み込み（Chord Roll から移植）と WAV への変換（DOM に依存しない） |
| `tests/` | テスト |
| `scripts/eval.ts` | 正解率の測定 |
| `scripts/synth.ts` | テストと測定に使う、ピアノ風の合成音 |
| `public/demo/` | デモ曲と、その正解のコード（そのまま公開されます） |
